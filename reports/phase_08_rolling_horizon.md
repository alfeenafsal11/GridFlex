# Phase 8 Report — Rolling-Horizon Control (Model Predictive Control)

## 1. Objective
Implement and validate the closed-loop Receding-Horizon Model Predictive Control (MPC) simulation framework, coupling multi-horizon forecasts, constrained LP optimization, and real-time physical battery actuation, strictly enforcing that only the first action from each optimization window is executed.

## 2. Receding-Horizon Control Loop Architecture

```text
               Decision Timestep t (Current Hour)
                               │
            ┌──────────────────┴──────────────────┐
            ▼                                     ▼
   Historical State                    Lookahead Predictions
   Current Battery SOC(t)              - Load: P_load(t+1 .. t+24)
                                       - Solar: P_solar(t+1 .. t+24)
                                       - Price: Price(t+1 .. t+24)
            │                                     │
            └──────────────────┬──────────────────┘
                               ▼
                   Constrained LP Optimization
                   Solve 24h Schedule via HiGHS
                               │
                               ▼
                     Extract FIRST Action Only
                     (P_charge*, P_discharge*)
                               │
                               ▼
                  Actuate Physical Battery
                  Under ACTUAL Conditions at t:
                  P_load(actual, t), P_solar(actual, t)
                               │
                               ▼
               Record Actual Grid Import, Curtailment,
               Internal Losses, and Resulting SOC(t+1)
                               │
                               ▼
                  Advance Timestep t <- t + 1
```

## 3. Operational Modes
1. **Forecast-Informed Optimization (System C — Deployable System)**:
   - Inputs to the optimizer are the multi-horizon predictions generated by the direct LightGBM models trained in Phase 5.
   - Operates strictly in the high-accuracy regime where LightGBM achieves superior short-term accuracy.
   - Represents a realistic, non-anticipative controller that has zero access to future actuals.
2. **Perfect-Foresight Optimization (System D — Oracle Reference)**:
   - Inputs to the optimizer are the actual future realization of load and solar.
   - Represents the theoretical upper bound on storage value with zero uncertainty.
   - Used strictly for gap analysis, never presented as an operational controller.

## 4. Physical Enforcement and Integrity
- **Real-Time Actuation**: Even if the optimizer's forecast deviates from reality, the physical battery simulator sanitizes the commanded actions against inverter ratings and SOC boundaries.
- **Node Energy Balance**: Conserved at every single rolling step without approximation error ($< 10^{-12}\text{ kW}$).
- **Zero Future Leakage**: The controller never applies future schedule actions ($h \ge 2$) directly; every future step is reforecasted and re-optimized as new measurements become available.
